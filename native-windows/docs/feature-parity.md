# Feature parity and acceptance

The baseline is `original-project/README.md`, its frontend, backend and source tests. The original Python/Node application and test suites were not executed during this native-only migration. The original native baseline built in Release and passed nine test groups; inspection then exposed missing writes, truncated exports, small/low-contrast text and unsafe UI/thread lifecycles.

The entire original feature set has native implementations. The acceptance column identifies concrete tests and remaining validation boundaries; actual configurations, commands and results are in [verification](verification.md). References to a test do not imply a passing run until that record confirms it.

| Original behavior | Native implementation | Acceptance and limits |
|---|---|---|
| Slate dark/light API/database workbenches | Win32 controls, slate palette, blue accents, sidebars and menus | Native dark/light render artifacts and navigation checks |
| Readable text and contrast | 16 logical px defaults, 100–150% interface scale, stronger muted/status colors, high-contrast system palette | Automated 4.5:1 palette checks and enlarged control bounds; physical display/screen-reader review remains |
| Syntax highlighting and completion | Rich Edit/TOM lexer, line numbers, undo-safe colors, SQL table/column/schema-qualified alias and quoted star expansion; JSON variables; script `pm` APIs and variable-name arguments | Native lexer/color/undo/completion/Enter-key tests; coloring and completion bounded above 512 KiB |
| Nested collections/folders and node editing | Searchable native tree, creation/rename/description/variables/auth/scripts, duplication/delete, selected-parent request save, JSON import/export | Protected persistence/import groups; GUI save/search and inherited runner tests |
| Multiple request documents | Native document selector and Ctrl+T/W/Tab, independent drafts/responses/consoles and concurrent requests | Whole-window invalid-draft retention and two real HTTP/script request jobs |
| Scoped variables and authentication | Global → collection → folder → environment → iteration data → local precedence; typed script values; None/Bearer/Basic/API key/inherit; header/query API keys | Resolver, encrypted restart, script precedence and real HTTP tests |
| HTTP methods, body types and options | WinHTTP JSON/raw/urlencoded/multipart binary files, redirects/TLS/timeouts and cancellation | Loopback native HTTP lifecycle tests; 64 MiB transfer bounds; attachment/editor bounds are visible |
| Structured assertions and script tests | Native assertions and compiled QuickJS `pm.test`/`pm.expect`, pre/post inherited scripts, console and scope changes | Script/assertion/real HTTP groups; timed loop/regexp/cancel/OOM/recursion/async rejection checks |

| cURL and code snippets | Native parser and cURL/requests/fetch/Axios generator, clipboard dialog | cURL round-trip auth/path/query/options/forms and snippet tests; generated JS syntax compiled natively; cURL files require attachment re-selection; unsupported browser fetch GET/HEAD bodies produce an actionable error, following the [Fetch standard](https://fetch.spec.whatwg.org/#dom-request) |

| Remote SQL/ODBC providers | Installed x64 ODBC driver discovery, native cancellable queries/result sets/schema/typed CRUD/export and protected profiles | Explicit schema required for browsing named namespaces; exact namespace matching prevents wrong-table edits. | MongoDB | Official native C driver, cancellable TCP, native Schannel TLS/auth, original JSON query operations and schema/grid/CRUD/export | Native compile/profile checks; no live MongoDB service was available |
| Redis | Native RESP protocol and Schannel TLS, original command/keyspace/grid operations | Native protocol fixture and cancellation checks; live Redis/TLS deployment remains unverified |
| Query documents/history/multiple results | Native query tabs, protected workspace/history, limits 1–10000, per-document database/results, result-set picker | Native document restore/history/limits/multiple-results and two-database close tests |
| Data grid | Paging/search/sort, typed insert/edit/delete, NULL/BLOB/numeric/JSON handling by provider capability | CRUD/full export and native row-dialog tests; very large values remain intact and read-only in the row dialog |

| Schema and ER tools | Columns/defaults/PK/FK actions/index columns/DDL copy; draggable protected ER coordinates and scrolling | Introspection, actual native schema/ER rendering, drag/restore and large-card bounds. ODBC table DDL reconstructs available metadata; bound catalog queries retrieve view definitions for supported families, with an explicit unavailable message otherwise |
| Mock REST API | Owned optional loopback server over SQL providers, table GET/POST, bound-key record GET/PUT/PATCH/DELETE and OPTIONS | Real SQLite/DuckDB HTTP CRUD, port lifecycle, cancellation and GUI Start/Stop tests; one-column record key required; remote drivers unverified; not enabled at startup |
| File picker/drop/clipboard | Native collection/API imports, SQLite attach, SQL load, multipart selection, text clipboard | Native dialogs/imports; virtual browser clipboard-file ingestion is not applicable |

| Deployment | Portable x64 Release archive, native dependency DLLs/notices and official signed VC runtime prerequisite | Guarded Release/package tests and dependency audit; clean-machine installation and app signing remain unperformed |

Intentional improvements include empty startup, larger text/stronger contrast, native controls, protected local values, explicit limits, checked writes and connection removal that preserves files. SQL formatting, mutation stepping, transaction rollback, complete exports, default-preserving typed editing and callback re-entry were repaired.

No remote-server, clean-machine, mixed-physical-monitor, universal offline, installer or application-signing acceptance is inferred from a successful local build. Provider capabilities remain visible; a missing ODBC driver or unreachable service produces an actionable error.
